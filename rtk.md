# Руководство по установке и настройке RTK (Rust Token Killer)

Это практическое руководство, составленное на основе успешной настройки RTK для работы с агентской средой -*OpenCode** и кастомным OpenAI-совместимым эндпоинтом (на примере кастомного провайдера).

## 1. Установка RTK

RTK — это прокси-инструмент на Rust, который перехватывает вывод команд и сжимает его перед отправкой в LLM, экономя до 60–90% токенов.

**Для Linux/macOS (Homebrew):**

```bash
brew install rtk
```

**Универсальный скрипт (Linux/macOS):**

```bash
curl -fsSL https://raw.githubusercontent.com/rtk-ai/rtk/master/install.sh | sh
```

## 2. Интеграция с OpenCode

Для перехвата команд, которые агент выполняет в терминале, необходимо установить специальный плагин.

> **Важно:** Плагин требует OpenCode версии **1.18.29 или новее**.

Выполните команду:

```bash
rtk init -g --opencode
```

*Флаг `-g` устанавливает глобальный хук, а `--opencode` создает файл плагина по пути `~/.config/opencode/plugins/rtk.ts`.*
После установки **обязательно перезапустите OpenCode**.

## 3. Настройка LLM для суммаризации (Delegate Reads)

Чтобы делегировать чтение больших файлов и генерацию кода дешевой модели, настройте файл конфигурации пайплайна.

**Расположение файла:**

- Linux: `~/.config/rtk/pipeline.toml`
- macOS: `~/Library/Application Support/rtk/pipeline.toml`

**Пример конфигурации для кастомного эндпоинта:**

```toml
schema_version = 1

[pipeline]
extends = "rtk:delegate-reads"

[upstream.trainee]
provider    = "openai"
model       = "junior"  # Имя модели, которое реально существует на вашем сервере
base_url    = "https://адрес.провайдера" # БЕЗ /v1 на конце!
api_key_command = "pass show my_provider/api-key" # Безопасное извлечение ключа
timeout_secs = 30

[task.bulk-read]
upstream = "trainee"

[task.code-write]
upstream = "trainee"
```

### ⚠️ Критические нюансы конфигурации (грабли, на которые легко наступить)

1. **Параметр `base_url`**: Указывайте корень API **без** `/v1` на конце. RTK автоматически добавляет путь `/v1/chat/completions`. Если указать `https://.../v1`, запрос уйдет на `https://.../v1/v1/chat/completions` и вернет **404 Not Found**.
2. **Параметр `model`**: Указывайте точное имя модели из вашего эндпоинта. Если сервер ответит `400 Bad Request: There are no healthy deployments for this model`, значит, вы указали несуществующее имя (например, `trainee` вместо `junior`).
3. **Ключи API (`api_key_env` vs `api_key_command`)**:
    - `api_key_env = "MY_VAR"` — берет ключ из переменной окружения (требует `export MY_VAR=...` в `~/.zshrc`).
    - `api_key_command = "pass show ..."` — безопасно запускает команду и берет ключ из stdout. Идеально для менеджеров паролей (pass, secret-tool).
    - *Никогда не вписывайте сам ключ (начинающийся на `sk-...`) в параметр `api_key_env`.*

## 4. Проверка работоспособности

Выполните эти шаги, чтобы убедиться, что всё настроено верно.

**Шаг 1. Валидация конфига:**

```bash
rtk pipeline validate
# Должно вывести: pipeline: ok (rtk:delegate-reads)
```

**Шаг 2. Проверка переписывания команд:**

```bash
rtk rewrite "git status"
# Должно вывести: rtk git status
```

**Шаг 3. Тест делегирования чтения (вызов модели):**

```bash
rtk bulk-read --question "О чём этот файл? Ответь одним предложением." ./README.md
```

Если вы получили осмысленный ответ от модели, значит связка `RTK -> Кастомный API -> Модель` работает.

**Шаг 4. Мониторинг экономии в OpenCode:**
Попросите агента в OpenCode выполнить любую bash-команду (например, `Run git status`). Затем в терминале запустите:

```bash
rtk gain
```

Вы должны увидеть статистику перехваченных команд и процент сэкономленных токенов (в нашем случае — 39.4% на команде `git status`).

## 5. Полезные команды

- `rtk gain --history` — детальная история экономии по каждой команде.
- `rtk init --show` — показывает статус установленных интеграций (Claude, OpenCode).
- Отключить телеметрию: `rtk telemetry disable`.
