# Как подключить Git к существующему сайту на 1С-Битрикс

Допустим, сайт уже работает, а вы подготовили его копию для разработки. Прежде чем поручать ИИ первую правку, сохраните исходную версию кода. Тогда будет с чем сравнить результат: какие файлы изменились, что именно добавилось и что не должно попасть на рабочий сайт.

## Что такое Git и GitHub

Git хранит историю изменений файлов. Коммит — это сохранённая версия выбранных файлов с сообщением о том, что изменилось. Первый коммит фиксирует исходное состояние кода, а следующие показывают, что менялось от задачи к задаче.

GitHub — сервис, где можно хранить удалённую копию репозитория Git. Коммит создаётся на вашей машине или dev-стенде, а команда `git push` отправляет его на GitHub. Git может работать и без GitHub; GitHub, в свою очередь, не заменяет резервную копию сайта и базы данных.

## 1. Выберите, какие файлы хранить в Git

Работайте в каталоге уже подготовленной копии сайта, а не на рабочем сервере. Если проект уже ведётся в Git, используйте существующий репозиторий: начинать историю заново не нужно.

Для первого коммита выберите файлы, которыми управляете вы: например, собственный шаблон, компоненты или код интеграции. В примере ниже собственный шаблон находится в `/local/templates/my-site/`. На вашем сайте путь может быть другим, в том числе внутри `/bitrix/templates/`. В этом случае следует перенести шаблоны в `local`, если это возможно.

Перед добавлением файлов создайте `.gitignore` в корне проекта. Вот пример стартового списка:

```gitignore
/.env
/.env.*
/bitrix/
/upload/
```

Это не универсальный список. Проверьте, где ваш проект хранит пароли, ключи, дампы базы, резервные копии и клиентские данные. Они не должны попасть даже в приватный репозиторий. И не начинайте с `git add .`: на существующем сайте проще сначала явно выбрать нужные файлы.

## 2. Сделайте первый коммит

Из корня копии сайта выполните команды. Замените `my-site` на имя своего шаблона:

```bash
git init -b main
git add .gitignore local/templates/my-site/
git diff --cached --stat
git diff --cached
```

Первая команда создаёт репозиторий с веткой `main`, вторая выбирает файлы для коммита. Две последние показывают список выбранных файлов и их содержимое в виде изменений. Проверьте, что вы добавили только нужный код и в нём нет секретов. Затем сохраните исходную версию:

```bash
git commit -m "Сохранить исходную версию шаблона сайта"
```

В этом примере первый коммит содержит только шаблон и `.gitignore`. Это начало истории кода, а не копия всего сайта. Другие каталоги можно добавлять отдельно после проверки.

## 3. Отправьте коммит на GitHub

Создайте на GitHub пустой приватный репозиторий. Не добавляйте при создании README, лицензию или `.gitignore`: первый коммит уже есть у вас на стенде. Затем используйте SSH-адрес своего репозитория. Для этого на машине, с которой вы отправляете код, должен быть настроен SSH-доступ к GitHub.

```bash
git remote add origin git@github.com:YOUR-ACCOUNT/YOUR-REPO.git
git remote -v
git push -u origin main
```

Команда `git remote -v` показывает, куда отправится код. После `git push` откройте репозиторий на GitHub и убедитесь, что в ветке `main` видны первый коммит и только те файлы, которые вы выбрали.

Сайт от этого не изменится: `git push` отправляет код на GitHub, а публикация на рабочий сервер — отдельный шаг. Теперь, когда ИИ изменит шаблон на стенде, вы сможете посмотреть разницу через `git diff`, проверить результат и сохранить правку отдельным коммитом.
